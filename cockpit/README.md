# Cockpit

| Part | Purpose |
|---|---|
| `app/` | Preact app with its own service worker (`app/sw/sw.ts`): message centre, assistant, figures of the apps, push settings |
| `app/sw/notification.ts` | Reads a push, builds the notification with up to three buttons and its tag (the browser shows as many as it can, Chromium two; the message centre shows all), and calls `cockpit.run_action` when a button is tapped, also on the lock screen; the outcome replaces the notification under the same tag |

| `../integration/` | Database tests of Cockpit, CRM and RadarAuditor together on a real PostgreSQL |

## One-tap actions
**Context:** a message in `cockpit.messages` may offer buttons (`actions`). | **Input:** a tap on the notification or in the message centre. | **Output:** `cockpit.run_action(message, token, action)` runs it and returns a German sentence.

| Where | What happens |
|---|---|
| Notification | The service worker sends the message id, the `action_token` from the push and the action with the public key; the sentence replaces the notification (same tag). Without network it says so and nothing is retried. |
| Message centre | The same call as the signed-in administrator; the message then shows which button was used, when, and the outcome. |
| Without a button tap | The notification opens the message's link as before. |

The server address and the public key reach the service worker at build time through `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, the same variables the app uses.

## Assistant
**Context:** page `/assistent`, one tap away: microphone button in the top bar on the phone, "Assistent" in the sidebar, and a shortcut on a long press of the installed app icon. | **Input:** a typed request or a voice recording. | **Output:** a row in `crm.assistant_requests`; the server worker answers with a notice of kind `assistent`.

| Step | What happens |
|---|---|
| Text | "Was soll ich tun?" (at most 2,000 characters), "Senden" calls `crm.ask_assistant(text, null)`. |
| Recording | Tap the microphone to start, tap again to stop and send. `getUserMedia` mono; an AudioWorklet (`app/public/audio/capture-worklet.js`, served from the app's own origin as the Content Security Policy requires) hands the samples to the page; after 60 seconds the recording stops by itself, the seconds left are shown. The screen stays on meanwhile (Wake Lock). |
| Conversion | `src/lib/audio/resample.ts` converts the device rate (mostly 48 kHz) to 16 kHz with an averaging filter; `src/lib/audio/wav.ts` writes mono 16-bit PCM WAV. A minute is about 1.9 MB, the bucket allows 4 MiB. Less than half a second is refused. |
| Upload | Raw bytes with type `audio/wav` to bucket `crm-assistant` at `anfragen/<crypto.randomUUID()>.wav`, then `crm.ask_assistant(null, path)`. If the upload or the request fails, the recording stays in memory: "Noch mal senden" repeats only the step that failed, "Aufnahme verwerfen" drops it. |
| List | "Letzte Anfragen": the last 20 requests with text or "Sprachaufnahme", status (Wartet, In Arbeit, Erledigt, Nicht erledigt), result and time. It reloads after sending, when a notice of kind `assistent` arrives and when the app comes back to the screen. |
| Failures | Microphone blocked, missing, busy or not supported, recording too short and upload failure each get their own German sentence. |

`app/public/_headers` allows the microphone for the app's own origin (`Permissions-Policy: microphone=(self)`); before, `microphone=()` blocked it in every browser. Mails the assistant drafts arrive as approvals of kind `assistant_mail`; like follow-ups (`follow_up`) they show "Senden" and "Nicht senden", which come from the database (`cockpit.on_crm_approval`, migration 006), not from the app. Notice kinds `termin`, `assistent` and `beleg` are labelled Termin, Assistent and Beleg; `audit-anfrage`, `audit-vorschlag` and `audit-termin` (migration 007) Audit-Anfrage, Terminvorschlag and Audit-Termin. Such a notice with buttons links to `/`, the message centre; a business taken in by `crm.request_audit` gets no notice „Neuer Kunde“ (`cockpit.on_crm_customer`).

## Checks

| Part | Command |
|---|---|
| App and service worker | `cd app && npm ci && npm run check && npm test && npm run build` |
| Edge Function | `deno check supabase/functions/cockpit-push/index.ts deploy/cockpit-push.ts` and `deno test --allow-read supabase/functions/cockpit-push deploy` |
| Deploy file after a change of the function | `deno run --allow-read --allow-write deploy/bundle.ts` |

Deploy the app: `npx wrangler@4 pages deploy dist --project-name repocity-cockpit --branch main`.
